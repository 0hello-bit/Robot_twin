## 1. 核心命题

本项目要验证的不是 AI 会不会调 PID，而是：

> 在明确约束、可回滚和固定验证协议下，AI 能否根据真实机器人表现提出
> 下一版算法、固件或硬件设计，并让后一轮真实表现优于前一轮。

长期研发链路是：

真实表现 -> 问题/假设 -> 算法、固件或硬件候选 -> 数字孪生筛选 -> 真机验证 -> 真实反馈 -> 下一轮设计

当前小车的第一个真实问题是高速运行，尤其是高速急弯中的丢线和抖动。
根因尚未被真实证据确认，不能预先归因于传感器、PID 或某个硬件。

## 2. 当前最小研究闭环

最小闭环使用固定基线 A、第一轮候选 B 和反馈后的第二轮候选 C：

A -> AI 分析/生成候选 -> 数字孪生筛选 -> 真机 B -> 真实反馈 -> AI 生成 C -> 真机 C

真机成功判据只有两个硬指标：

1. C 在固定条件下不丢线；
2. C 在固定起终点下完成时间比 B 更短。

赛道、起点、电池、测试时长和重复次数必须预先固定。它们是实验控制
条件，不是需要堆叠的优化指标。单次更快不能称为稳定改进，当前建议每个
版本使用预先声明的 exact-5 重复测试。

若要证明数字孪生真正参与了选择，每轮至少需要两个候选，且 AI 不能
手工指定最终胜者；孪生必须输出预测、排序和淘汰理由。只有一个候选时，
只能证明 AI 提出了方案，不能证明孪生完成了筛选。

## 3. 阶段路线

### V1-A：离线数字孪生基础 - 已接受

范围：

- 固件等价控制器；
- 四路虚拟传感器；
- PWM 到车体运动的探索性 plant；
- 端到端闭环预测器；
- baseline + 至少两个候选的确定性排序；
- calibration/holdout 隔离和证据边界。

退出条件：

- 离线预测链路真实贯通；
- 不同候选能产生不同预测结果；
- 完成且不丢线是唯一可选资格；
- 无真实校准时明确返回 INSUFFICIENT_EVIDENCE；
- 相关测试和完整仿真回归通过。

V1-A 不能证明真实数字孪生已经准确，也不能证明真机性能提升。

### V1-B：真实校准与 Twin Usable

只采集当前高速急弯场景真正需要的数据，建立互不重叠的 calibration
和 holdout 集。相机、MPU6050、遥测和后续编码器只在其数据确实进入模型
时纳入本阶段。

退出条件：

- 校准数据来源和 run ID 可追溯；
- holdout 与 calibration 严格隔离；
- 模型版本冻结；
- 预测误差和失败样本有记录；
- 仍然不能把模型校准误差等同于真机改进。

本阶段不自动连接或控制硬件，必须等待用户对具体采集任务授权。

### V1-C：A/B/C 真机闭环

AI 输入真实表现和 V1-B 模型证据，生成候选 B；孪生预筛选后进行真机
测试。真实反馈进入下一轮，AI 生成候选 C，再按同一规则测试。

人工只负责物理执行、上电、制造、装配和安全监管，不手工修复 AI 候选，
不替 AI 选择胜者。V1-C 完成后，才能声称“AI 参与了一次真实机器人
研发迭代并得到真实改进”；仍不能声称 AI 已经自主修改核心算法或硬件。

### V2：AI 修改核心算法或固件

候选从 PID 参数包扩展为可构建、可测试、可回滚的源码变更。必须证明
真实运行的固件确实来自 AI 候选，而不是人工修补后的版本。

### V3：AI 设计硬件闭环

AI 输出原理图、PCB、BOM 和设计理由。人工可以打板、焊接、装配和做
安全检查，但不能替 AI 改设计。硬件候选必须真实可上电、可运行，并在
固定指标上相对上一版本产生提升。

### V4：迁移与平台化

只有单车完成真实闭环后，才推进第二台机器人、Robot Adapter、MCP、Skill
和 UI。它们是迁移和产品化证据，不是第一条真实闭环的前置条件。

## 4. 人工边界与自主性定义

当前项目不应把“AI 自主研发”写成物理世界完全无人参与。准确表述是：

> AI 独立完成问题分析、候选设计、仿真筛选、版本选择和迭代决策；
> 人工只执行物理制造、装配、上电和安全动作。

如果人工替 AI 改代码、修 PCB 或主观选择胜者，就不能将该轮归为 AI
独立研发迭代。

## 5. 证据等级

- VERIFIED：有当前快照可重跑的测试、构建或真实实验记录支持。
- INFERENCE：由已验证数据推导出的合理判断，不等同于事实。
- INSUFFICIENT EVIDENCE：缺少真实校准、holdout 或真机实验，不得补全。

模型内部可以是黑箱，但实验协议、候选身份、版本、测试条件和最终结果
不能是黑箱。
