# 巡线 PID 自主优化闭环 - V1 设计规格

**状态：** 已确认设计，待实现计划

## 1. 目标与边界

本规格定义 Robot Twin AI 的首个可验收闭环：在用户现有的固定巡线赛道上，系统自动寻找更优的巡线 PID 参数，并以数字模型预筛选和重复实机测试证明改进有效。

闭环目标按优先级排序：

1. 保持安全并完成赛道；
2. 降低巡线误差；
3. 在前两项不退化的前提下缩短完成时间。

本版本只允许修改运行时 PID 参数。AI 不自动修改控制源码、烧录固件、改变电路或 PCB。轮速 PID 不属于本版本，因为当前大圣小车工程未具备已验证的轮编码器反馈链路。

## 2. 成功定义

一次优化活动由一个基线参数包和不超过 12 个候选参数包组成。每个参数包在相同赛道、相同测试规程下最多运行 5 次。

候选参数只有在以下条件同时满足时才可标记为“接受”：

- 有效完成率不低于基线；
- 平均巡线误差比基线降低至少 15%；
- 最大巡线误差和出线次数不高于基线；
- 在以上条件满足后，平均完成时间比基线缩短至少 5%；
- 至少 5 次有效运行中没有触发安全停止。

若没有候选达到全部条件，系统应保留基线参数，并明确报告“本轮无可接受改进”，而不是选择相对较好的失败方案。

## 3. 固定测试规程

- 使用用户现有赛道作为本版本唯一验收场景；
- 每次活动开始前记录赛道版本、环境、负载、电池电压或供电状态；
- 每次运行使用同一起点和终点、同一允许速度上限；
- 有效运行必须从起点开始并由系统识别完成或终止原因；
- 任何人工移动小车、换电、调整传感器高度或改变赛道后，必须开始新的活动，不得与旧活动混合比较。

## 4. 系统职责

### STM32 固件

固件继续执行实时巡线控制，并提供受约束的参数接口。它必须：

- 接收带版本号、校验和和活动 ID 的参数包；
- 仅在安全边界内应用 `Kp`、`Ki`、`Kd` 和速度上限；
- 回传参数已生效的确认与实际生效值；
- 持续上报传感器状态、巡线误差、PID 输出、四路 PWM、运行状态和终止原因；
- 接受停止和恢复基线参数命令；
- 在通信失联、连续出线、运行超时或超出安全边界时停止并记录原因。

安全边界不是由 AI 临时决定。每个参数的最小值、最大值和单次变化幅度必须在固件配置中声明；任何边界缺失时，自动模式拒绝启动。

### 电脑端闭环服务

电脑端是活动协调者，不直接输出 PWM。它负责：

- 创建活动、运行和参数版本；
- 保存原始遥测和汇总指标；
- 向数字模型请求候选预筛选；
- 将通过预筛选的单个候选参数包下发给 STM32；
- 等待 STM32 参数确认后启动一轮测试；
- 根据安全规则停止、回滚或进入下一候选；
- 生成可追溯报告。

### 数字模型 — v1_twin 最小可信二维数字孪生

V1 的数字模型（`simulation/digital_twin/v1_twin/`）是用于 PID 候选排序的最小可信二维数字孪生，不以三维显示效果作为验收依据。它由 6 个子模块构成：

| 模块 | 文件 | 职责 |
|------|------|------|
| 数据契约 | `v1_twin_schema.py` | V1Pose、V1SyncFrame、V1SensorModelConfig 等不可变数据结构 |
| 固件等价控制器 | `v1_twin_controller.py` | 与 STM32 main.c PID 公式完全一致的控制器仿真 |
| 虚拟四路传感器 | `v1_twin_virtual_sensor.py` | 基于位姿+赛道地图的离散传感器几何模型，阈值与固件 SENSOR_THRESHOLD 一致 |
| 车辆行为模型 | `v1_twin_plant.py` + `v1_twin_identification.py` | 四路 PWM→vx/vy/omega 低参数辨识模型 |
| 外部真值链 | `v1_twin_camera.py` + `v1_twin_calibration.py` + `v1_twin_pose_tracker.py` + `v1_twin_sync.py` | 俯视相机→AprilTag 位姿→时间同步 |
| 验证与版本 | `v1_twin_validator.py` + `v1_twin_model_registry.py` | G1-G8 可信门阈值验证，模型冻结与版本管理 |

#### 可信门阈值（G1-G8）

模型只有通过全部 8 道可信门后才可用于候选预筛选：

| ID | 门名称 | 通过标准 |
|----|--------|---------|
| G1 | 摄像头实时流 | fps ≥ 20, drop ≤ 5%, 时间戳单调 |
| G2 | 相机标定 | 重投影误差 p95 ≤ max(2 px, 5% 黑线宽度像素) |
| G3 | 静态位姿 | 有效率 ≥ 95%, x/y p95 ≤ 5% 黑线宽度, yaw p95 ≤ 2° |
| G4 | 时间同步 | 匹配覆盖率 ≥ 95%, 时间差 ≤ max(1帧相机周期, 1帧遥测周期) |
| G5 | 传感器模型 | holdout macro-F1 ≥ 0.90 |
| G6 | 轨迹模型 | holdout 横向误差 p95 ≤ 0.5 × 黑线宽度 |
| G7 | 指标预测 | holdout RMS ≤ 15%, 最大误差 ≤ 15%, 完成时间 ≤ 10% |
| G8 | PID 排序 | Spearman ≥ 0.70, danger recall = 100% |

任何一门失败 → 模型 NOT READY → 4C 不得开始。

#### 校准与 holdout 硬隔离

模型按 run_id 严格分离校准集与 holdout 集，程序硬检查两集合交集为空。模型冻结后不得查看 holdout 数据或调整参数。最终 holdout 使用模型从未见过的安全 PID 组采集，每组恰好 5 次完整运行。

### 优化器与 AI — 确定性候选生成 + 模型预筛选

**优化器（Task 4C，`v1_twin_candidate_generator.py` + `v1_twin_ranker.py`）** 在固件声明的 Kp/Ki/Kd/speed_max 边界内，以确定性算法生成不超过 12 个候选 PID 参数包，经冻结后的 v1_twin 模型预筛选后输出排序列表。

候选生成使用网格采样或 Sobol 序列等可复现方法，拒绝随机退化或不可解释的候选。每个候选附带参数包、模型预测指标和 rationale 说明。

**AI Agent** 的职责限于调用数据读取、模型预筛选、参数部署（经 Orchestrator）、测试和报告工具，解释候选依据并决定活动流程。AI 不得绕过固件安全范围、伪造遥测或将自然语言内容直接转为未校验的电机命令。

**关键限制：** 4C 必须等待 4B-8 READY 后才能开始。模型未通过 G1-G8 可信门前，不得进行候选预筛选。

## 5. 数据与版本契约

每个活动必须有唯一 `campaign_id`。每次运行必须关联以下不可变信息：

- `run_id`、`campaign_id`、机器人 ID、固件版本和赛道版本；
- 参数包版本、`Kp`、`Ki`、`Kd`、速度上限、校验和和 STM32 生效确认；
- 时间戳、四路巡线传感器状态、巡线误差、PID 输出、四路 PWM；
- 运行阶段、完成时间、完成/出线/超时/安全停止等终止原因；
- 平均误差、均方根误差、最大误差、出线次数和有效性判定；
- 数字模型版本、预测结果、置信度和预筛选结论。

参数包状态依次为 `candidate`、`simulated`、`deployed`、`verified`、`accepted` 或 `rejected`。任何失败运行均不得删除，必须保留为 `rejected` 的证据。

## 6. 自动化流程

```text
创建活动并运行基线 5 次
  -> 计算基线指标并校准数字模型
  -> 生成一个受边界约束的候选 PID 参数包
  -> 数字模型预筛选
  -> STM32 校验、应用并确认参数
  -> 真机最多运行 5 次
  -> 计算指标并与基线比较
  -> 接受候选，或回滚基线并记录拒绝理由
  -> 未达到活动上限时处理下一个候选
  -> 生成报告并结束活动
```

一次只允许一个候选处于 `deployed` 状态。下一候选部署前，系统必须确认前一候选已完成、停止或回滚。

## 7. 安全与故障处理

- 自动模式开始前，操作者确认赛道净空、小车可安全停止、供电正常；
- 候选参数必须通过格式、版本、校验和和范围检查；
- 通信确认超时、遥测中断、连续出线、单次运行超时或安全停止后，立即恢复基线参数并结束该次运行；
- 活动达到 12 个候选或任一候选出现预定义严重异常时，停止继续探索并输出报告；
- 系统保留人工急停优先级，AI 或电脑端均不得屏蔽它；
- 自动参数部署不等价于自动烧录。固件变更始终需要独立审批和验证流程。

## 8. 首次验收演示

1. 固化一组可完成赛道但误差较大的基线 PID；
2. 在固定赛道完成 5 次基线运行；
3. 系统自动完成候选生成、模型预筛选、部署确认、真机测试、回滚和记录；
4. 展示一组被接受的参数，或展示“无可接受改进”的完整拒绝证据；
5. 报告必须能回放每次运行，并说明最终结论与基线的量化差异；
6. 整个演示不依赖人工挑选具体 PID 数值，也不允许在活动中手工修改结果。

## 9. 非目标

- 轮速 PID、姿态 PID、在线强化学习；
- AI 自动修改控制代码、烧录固件、改动原理图、PCB 或器件；
- 以单次最佳成绩替代重复测试；
- 将 3D 动画或语言模型说明当作性能提升证据；
- 不同赛道、负载或供电条件下未分组的数据比较。
