# Camera configuration handoff: 1920x1080 at 30 FPS

Status: `OFFLINE_CONFIGURED_HARDWARE_PROBE_VERIFIED`

## Decision

The canonical camera configuration is now:

- EMEET SmartCam C960, DirectShow;
- `1920x1080`;
- `MJPG`;
- requested and accepted project frame rate: `30 FPS`.

The shared constants live in `tools/camera_toolchain/camera_common.py`. The
synchronized capture, Gate 0, preview, calibration capture, homography
capture, and camera probe tools reuse those constants.

## Hardware probe evidence

On 2026-08-08, camera index 1 was probed without starting or controlling the
car:

- `1920x1080@30`: property mode `1920x1080@30.000`, all 30 frames readable;
- long read test: `29.6 FPS` measured, frame shape `(1080, 1920, 3)`;
- `1920x1080@60`: property mode falsely reported `@60.000`, but sustained
  reads measured about `29.5 FPS` with frame shape `(1080, 1920, 3)`;
- conclusion: the highest verified stable output at 1080p is about 30 FPS;
  do not configure 60 FPS from the driver property alone.

## Evidence protection

The synchronized capture now accepts an expected frame size and records the
actual `frame_width`/`frame_height` in every frame-index record. The canonical
real capture path passes `(1920, 1080)` and fails closed with
`camera_frame_dimensions_mismatch` if `cap.read()` returns another shape.

This protects against the earlier contradiction where camera properties said
1280x720 while retained failure images were 640x360.

## Calibration boundary

The existing exploratory C960 calibration profile and intrinsics are still
`1280x720`. They were not scaled or rewritten. A real synchronized 1080p run
must wait for a fresh 1080p intrinsics and homography calibration; using the
old profile would be rejected by the existing dimension gate.
